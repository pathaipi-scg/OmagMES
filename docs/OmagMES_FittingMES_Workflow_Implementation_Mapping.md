## 3. Important FittingMES implementation cautions

- FittingMES contains multiple quantity/reject workflows (whole-lot ProductionData, per-press PressProduction, newer `/reject`, legacy Wet Reject, and final Production Reject classification). They are not interchangeable.
- Some FittingMES workflows update current records in place; not all keep detailed before/after revisions. OmagMES requires quantity correction traceability.
- FittingMES migrations assume existing schema, stored procedures, views, and triggers. For example, [027_shift_aware_press_production.sql](../../FittingMES/sql/027_shift_aware_press_production.sql) explicitly guards for database `SB23`; it is not portable to OMAG.
- The FittingMES code/test suite does not establish that OMAG has compatible sources, masters, deployed procedures, or permissions. Do not run its SQL against OMAG.
- The production UI uses server-rendered Jinja because that is the existing reference stack; OmagMES uses the separately approved React + TypeScript + Vite frontend and FastAPI REST API.

## 4. OmagMES transfer decisions

**Reuse as behavior:** explicit SAVE, validation on the server, transaction/concurrency patterns as applicable, active master-driven dynamic rows, editable but controlled records, durable Lot ID, and calculations kept separate from persistence.

**Do not reuse blindly:** schema/table names, Product family numbering, machine hierarchy, shift/Thai-year rules, R99 balancing, capability speed/OEE joins, legacy Wet Reject trigger assumptions, or the absence of detailed correction history.

**Unresolved before production SQL integration:** authoritative OMAG Product/Color/Reject Reason masters; actual `REJECT_WET` columns/tag/reason mappings; verified `product_count` timestamp and duplicate policy; approved source read role; business approval of lot boundary/autocal attribution, source gaps, and migration rollback. At the time of this original FittingMES workflow review, `.env` differed from the owner-specified SQL host and no connection was attempted. A later explicitly authorized SELECT-only PRESS check is documented in [the AutoLot/Mould reference](OmagMES_AutoLot_Mould_Assignment.md); its tested login had broad write/DDL permissions and is not approved for application use.
